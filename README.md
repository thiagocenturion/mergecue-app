# MergeCue

**PRs move forward. You stay in flow.**

MergeCue is a native macOS menu bar app for GitHub, GitLab and Bitbucket pull/merge requests, with a bundled MCP
server (`mergecue-mcp`) that hands review work to the coding agent you already use. Product brief: `docs/PLAN.md`.
Module contract: `docs/ARCHITECTURE.md`. Conventions: `CLAUDE.md`. Decisions: `DECISIONS.md`.

## Run from Xcode (Debug)

1. Open `MergeCue.xcodeproj` (Xcode 26 or later).
2. Select the **MergeCue** scheme and **My Mac**.
3. Press **⌘R**.

The app adds its icon to the menu bar. The Debug scheme passes `--show-window`, so the main window opens as well.
MergeCue is a menu bar app (`LSUIElement`): it shows a Dock icon only while the main window is open.

Signing uses the **Apple Development** identity of team `TTSKDZ455K` (manual signing, Hardened Runtime, no App
Sandbox). On a Mac without that certificate, change the team under *Signing & Capabilities* for both targets
(`MergeCue` and `mergecue-mcp`), or build ad-hoc with `SIGNING=adhoc scripts/build-app.sh`.

### What the "Preview data" badge means

The engine is not wired into the app yet. Until it is, the app always runs on a **synthetic, in-memory preview
backend**: every account, pull request, task and agent you see is made up, and nothing is fetched from GitHub, GitLab
or Bitbucket, stored, posted or launched. Every screen shows a **Preview data** badge (and the window subtitle says
so) so this data can never be mistaken for live data.

Scheme options (*Product ▸ Scheme ▸ Edit Scheme… ▸ Run ▸ Arguments*), all off unless noted:

| Option | Values | Effect |
| --- | --- | --- |
| `--show-window` (argument, on) | | Open the main window at launch. Untick to start in the menu bar only. |
| `MERGECUE_PREVIEW_VARIANT` | `standard` (default), `authExpired`, `allCaughtUp`, `noAccounts` | Preview scenario. |
| `MERGECUE_BACKEND` | `preview` (default), `demo`, `live` | Backend selection. `demo` and `live` are not available yet and fall back to `preview` (see `App/MergeCueApp.swift`). |

## Command line

```sh
scripts/build-app.sh [Debug|Release]   # regenerate project, xcodebuild, copy to dist/MergeCue.app, verify signing + icon
scripts/run-app.sh [--menu-bar-only]   # build Debug and open dist/MergeCue.app
scripts/run-preview.sh [variant]       # run the UI shell from SwiftPM, without an app bundle
scripts/test.sh                        # swift build + swift test for every module
```

`SIGNING=adhoc scripts/build-app.sh` signs ad-hoc (no certificate needed, used by CI).

## Project layout and regenerating the Xcode project

All code lives in the SwiftPM package at the repository root (`Package.swift`, `Sources/`, `Tests/`).
`MergeCue.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` and only adds:

- the `MergeCue` app target (`App/`: `@main`, `Info.plist`, entitlements, `Assets.xcassets`), linking the package
  products `MergeCueUI` and `MergeCueRuntime`;
- the `mergecue-mcp` tool target (`Sources/mergecue-mcp`), embedded as `MergeCue.app/Contents/MacOS/mergecue-mcp`.

The project references the root package as a local package (relative path `.`, next to `MergeCue.xcodeproj`), so
the app always builds against the working tree. The project navigator shows only the app files, `Package.swift`,
`project.yml` and this README; use Open Quickly (⇧⌘O) to jump to any package source. Keep one Xcode window on this
checkout: don't open `Package.swift` on its own while the project is open, because Xcode opens a package in only one
workspace at a time.

After changing `project.yml`, regenerate and commit the project:

```sh
brew install xcodegen          # once
scripts/generate-project.sh    # xcodegen generate + one normalisation step
```

Use the script rather than plain `xcodegen generate`: XcodeGen would also add a navigator folder for the root package
named after the checkout directory, so every clone or worktree would produce a different project. The script
removes that folder and keeps the output identical everywhere. `scripts/build-app.sh` runs it on every build, and CI
fails if the committed project is out of date.
