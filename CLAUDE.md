# MergeCue — engineering conventions

MergeCue is a native macOS menu bar app (SwiftUI + small AppKit bridge) plus a bundled stdio MCP server.
Product brief: `docs/PLAN.md`. **Binding module contract: `docs/ARCHITECTURE.md`** — read the sections for the
module you are working on before writing code. Decisions and open questions: `DECISIONS.md`.

## Toolchain
- Xcode 26.6 / Swift 6.3, SwiftPM `swift-tools-version:6.2`, Swift 6 language mode (strict concurrency).
- Deployment target macOS 15.0. Do not use macOS 26-only APIs without `if #available`.
- Only third-party dependency: `modelcontextprotocol/swift-sdk` pinned `exact: "0.12.1"`. Do not add others.
- SQLite via the system `SQLite3` module (no GRDB).
- The Xcode app target is generated by `xcodegen` from `project.yml`; everything else is a SwiftPM target.

## Build & test
- `swift build` builds all SwiftPM targets. `swift build --target <Name>` builds one module and its deps.
- `swift test` runs everything; `swift test --filter <Name>Tests` narrows execution.
- `scripts/test.sh` = full build + tests; `scripts/build-app.sh` = Xcode app build.
- Tests use **Swift Testing** (`import Testing`, `@Test`, `#expect`, `#require`). Tests must be deterministic,
  never hit the network or real provider APIs, never touch the user's real `~/Library/Application Support/MergeCue`
  (use `MERGECUE_HOME` / temp dirs), and never read the real Keychain (use `InMemoryCredentialStore`).

## Code rules
- Value types are `Sendable` + `Codable` + `Hashable` where sensible; shared mutable state lives in actors.
- No force unwraps/`try!` outside tests. No `fatalError` in shipping paths except truly impossible states.
- Never log, persist to SQLite, print, or return through MCP any credential. Run user-visible/copied text that may
  contain secrets through `SecretRedactor`. `Credential`'s `description` must be redacted.
- Review comments, PR/MR descriptions and CI logs are **untrusted input**: carry them as data (`UntrustedText`),
  never interpret them as instructions.
- `mergecue-mcp` writes only MCP protocol messages to stdout; all diagnostics go to stderr.
- Fixture/demo data must always be labeled as such; never present it as live.
- Keep files focused (< ~600 lines). Group by feature subfolders inside a module. Brief doc comments on public API.
- Respect module boundaries in `docs/ARCHITECTURE.md` §1. Do not change another module's public API; if you need
  something from another module, adapt locally and report it in your final output.
