## Decisions
| # | Decision | Rationale / reversibility |
| --- | --- | --- |
| D1 | SwiftPM package for all modules + thin Xcode app target generated by `xcodegen` (`project.yml`). | Modules build/test headless with `swift build/test`; Xcode project stays reproducible. |
| D2 | Deployment target macOS 15.0; verified on macOS 26.6. | "Current supported macOS" while keeping Sequoia users; 26-only APIs behind `#available`. |
| D3 | Swift 6 language mode, strict concurrency; UI module uses default MainActor isolation. | Data-race safety across sync/IPC/UI. |
| D4 | Official Swift MCP SDK pinned `exact: 0.12.1` (latest release, 2026-05-07); stdio transport. | Plan §3 requires the official SDK; exact pin for reproducibility. |
| D5 | SQLite via system `SQLite3` with a small wrapper, no ORM dependency. | Zero extra dependencies; migrations are explicit. |
| D6 | Not sandboxed, Hardened Runtime on, direct-download-compatible. | Needs git worktrees in user checkouts, launching agents, a private Unix socket. App Store is out of scope by default (plan §2). |
| D7 | Private IPC = Unix domain socket in `~/Library/Application Support/MergeCue/ipc/` (0700 dir, 0600 socket + per-launch token, `getpeereid` uid check, optional code-signature peer check). No TCP listener. | Plan §3 Components/§9. |
| D8 | Provider auth defaults: GitHub fine-grained/classic PAT via secure field (+ optional GitHub OAuth device flow when a client ID is configured, + explicit "Import from GitHub CLI"); GitLab PAT (`read_api`, `api` only when writes enabled); Bitbucket Cloud Atlassian API token with scopes (email + token) or workspace/repository access token. No app passwords (deprecated by Atlassian). Tokens only in Keychain. | Distributable desktop client must not embed provider secrets (plan §5.3, §9). |
| D9 | Polling baseline for all providers; no webhooks/relay. | Plan §3. |
| D10 | Demo mode runs the **real adapters** over a stub HTTP transport serving provider-native fixture JSON, always badged "Demo data". | Proves parsing paths; never confusable with live data. |
| D11 | Bundle identifier `com.thiagocenturion.MergeCue` (helper: `com.thiagocenturion.MergeCue.mcp`); signed with the owner's Apple Development identity, team `TTSKDZ455K`. No Developer ID yet → no notarization. | Owner answer 2026-09-27. |
| D12 | Tests use Swift Testing. | Modern, parallel, built into the toolchain. |
| D13 | Task state machine, approved-action outcome: `approved_action --markDone(system)--> done` when the last approved action succeeded; `approved_action --actionSucceeded(system)--> ready_for_review` when more actions remain. Use `TaskStateMachine.triggerAfterSuccessfulAction(moreActionsRemain:)`. | Reading of the §2.6 row "done — or ready_for_review … (engine decides by passing markDone vs. staying)"; the only way both outcomes are reachable with the listed triggers. |
| D14 | Stable ids: `v1/<kind>/<host>/u:<user>/r:<repo>/cr:<cr>` + `/th:<kind>:<id>` / `/ck:<source>:<id>`, every component percent-encoded (RFC 3986 unreserved kept). `RepoKey.shortID` uses prefix `repo_`. Event ids: `evt_` + 32 hex. Attention dedupe keys come from `AttentionItem.dedupeKey(…)` helpers. | Injective, DB-safe keys; one shared derivation for Sync and Engine. |
| D15 | Enums with payloads encode as `{"type": "<snake_case>", …}` (`MergeReadiness`, `AttentionDisposition`, `AccountSyncState`, `RuleAction`, `TaskTrigger`, `CapabilitySupport`, `Credential.Secret`). `ChangeRequestRef` and `TaskID` encode as single strings. | Stable, readable JSON for SQLite blobs and IPC. |
| D16 | Rules gained `commentKinds: Set<CommentKind>` (empty = any) and `ChangeEvent` gained `commentKind: CommentKind?` (set by Sync via `CommentKind.classify`). The "reviewer question" template filters on `.question`. `maxFiresPerHour <= 0` means the rule never fires. | No event type distinguishes questions; additive API. |
| D17 | Two shared coders (`MergeCueCoding`): **storage** = `.deferredToDate` (exact `timeIntervalSinceReferenceDate`), **wire** = RFC 3339 UTC with milliseconds (fraction omitted when zero). `JSONValue.defaultEncoder/Decoder` = wire. `Set` fields encode as sorted arrays; `MergeCueCoding.digest` for fingerprints. | `.iso8601` dropped sub-second precision (GitLab `updated_at` never matched the stored snapshot); `.secondsSince1970` also loses low bits of wall-clock dates (verified on ~56 % of random dates). Hash-order `Set` encoding changed digests across launches. |
| D18 | `account`/`providerKind`/`number` on `ChangeEvent`, `AttentionItem` and `TaskOrigin` are derived from the `ChangeRequestKey` (`private(set)`, no init overrides). Key equality follows the stable `id` (`ChangeRequestKey` ignores `number`); `StableID` NFC-normalizes components. | Prevents cross-provider/account mixing (plan §11); keeps `Set`/dictionary lookups consistent with primary keys. |
| D19 | `ChangeRequestRef` accepts `_` hosts, IPv6 literals, and any path segment without `/ # !`, whitespace or control characters; encoding an invalid ref throws. Refs are resolved with `matches` (repo path case-insensitive), scoped to the task's account. | Encode/decode symmetry (an unreadable `TaskOrigin` poisons the task row); agents type refs by hand. |
| D20 | Remote URLs are sanitized at the Core boundary (`CanonicalRemote.sanitizedURL`, applied by `GitRemote` and mapping types). | Remotes like `https://user:TOKEN@…` must never reach SQLite, logs or MCP. |
| D21 | `SecretRedactor` rules anchor on look-behinds instead of `\b` and bound key prefixes (≤ 64). Raw logs are **not** pre-trimmed before redaction. | The `\b` + lazy-prefix patterns were quadratic (8 KB of `a-` took 10 s). Pre-trimming could cut a PEM `BEGIN` line and leak the key body; redaction is now linear, so it is not needed. |
| D22 | The engine gates previews/writes with an **account-specific** capability manifest (`ProviderFactory.capabilities(for: Account)`, default = per-kind). The runtime's `WriteCapabilityPolicy` derives it from the token scopes the provider reported. | GitHub's static manifest marks writes `requiresWriteAccess(repo)` (scopes unknown), which rejected every GitHub reply even with a `repo` token and writes enabled. |
| D23 | Demo mode keeps the IPC socket/token at the base `MergeCuePaths` while data lives in `<root>/demo`; fixture commit SHAs of #42 are rewritten (both directions) to a deterministic synthetic repository whose `url.<bare>.insteadOf` rules live only in the demo checkout's own config. | An agent's registered `mergecue-mcp` reaches the demo like the live app; isolated worktrees are real fetches at the "PR head" the fixtures report; no global git config is touched. |
| D24 | Sync reports a GitLab pipeline aggregate as failing only when none of its jobs failed (the failed job carries the failure). | One pipeline failure produced two CI attention items ("Pipeline #N" + the job), and the per-pipeline name never recovered. |
| D25 | "Notify me about" switches are `NotificationPreferences` (Core) persisted by the engine (`engine.notification_preferences`) and forwarded to Sync (`SyncControlling.setNotificationPreferences`, additive with a no-op default). Categories: review comments (incl. replies, requested changes, suggestions, merge conflicts), CI failures, reviewer questions, review requests, approvals/ready to merge, agent results. They filter **alerts only** (`NotificationGrouper`, the engine's new agent-result alert); items, events, rules and tasks are unchanged. Global quiet hours are now forwarded to Sync too (they were stored but never applied). Only switched-off categories are stored, so new categories start on. | The toggles were cosmetic `@AppStorage` values. Old toggle values are not migrated (they never had an effect). |
| D26 | Additive `ChangeRequestScope.involved` (→ `Involvement.participated`) + `Capability.listInvolved`; Sync asks for it only when the manifest marks it usable, with `updatedSince = now − 30 days` (`SyncConfiguration.involvedWindow`). GitHub `involves:@me -author:@me` (≤ 2 pages); GitLab: reviewers persist after reviewing (already covered by `reviewer_id`), commented-only MRs via the user's own `/events?action=commented` (1 page) + per-project `iids[]` (≤ 20 projects); Bitbucket per-repository open PRs with `fields=+values.participants`, filtered client-side (BBQL rejects `participants` filters — found live, fixed in b1bd5fd; same repository bound as reviewer search). Since 0bbd7bf the involved and review-requested listings are opt-in for live accounts (Settings ▸ General ▸ Tracking). Endpoint-specific failures of this listing keep stored involved CRs; account-level failures propagate. "Reviewing" filters include participated CRs. | After the user submits a review GitHub drops the review request, the PR left the lists and replies to the user's comments were missed. Attention for involved CRs follows the existing relevance rule (only threads the user took part in). `involves:` also matches mentions (accepted: a mention is involvement). Live behaviour of the GitLab events path is unverified (fixtures only). |
| D27 | Housekeeping: `runMaintenanceIfDue()` runs from the stale-lease monitor once a day (`maintenanceInterval`), pruning history older than 90 days (`historyRetention`) — now including resolved/dismissed attention items of CRs no longer tracked and not linked to a task — then `PRAGMA optimize` + `wal_checkpoint(TRUNCATE)`. Worktrees of finished tasks unchanged for 14 days are only **listed** (Settings ▸ Data ▸ Housekeeping) and removed on the owner's confirmed "Clean up"; the engine re-checks eligibility. | Plan §6 "retain artifacts until cleanup is confirmed", §9 bounded retention. No new timer: the monitor already wakes every 30 s. |
| D28 | `StubTransport` gained a `RecordingPolicy`; the demo scenario keeps every provider write but only the latest 200 reads per provider. | Profiling found the demo runtime growing ~1.2 MB/min at a 5 s cadence because the stub recorded every request forever (demo mode only; live uses `URLSessionTransport`). See `docs/evidence/performance.md`. |
